# Exp1 → Exp3: полный список отличий

Сравнение по артефактам прогонов `20261024-public-original` обоих экспериментов. Числа — из сохранённых `manifest.json`, `summary.json`, `score.json` и промптов, а не из пересказа.

## 1. Что осталось одинаковым

Чтобы отличия были сопоставимы, перечислено сначала то, что совпадает:

- Train-выборка `data/public_train.csv` (SHA256 `aedc2d32…`), test `data/public_test.csv` (`2554cc2d…`), язык `original`.
- Источник разборов: baseline train-прогон `baseline/results/20261024-public-train-original`, 40 несовпадений с gold из 150.
- **Таблица разборов А/Б идентична побайтово** — exp3 переиспользует `exp1/artifacts/20261024-public-original/analyses.jsonl` и проверяет его хеш, хеш train, хеш baseline-промпта и полноту (150/150).
- Judge: `gemini/gemini-flash-latest` (отвечает `gemini-3.8-flash`), температура 0, `max_output_tokens` 2048, таймаут 120 с, без автоматических повторов, native structured output `{"label":"good"}` / `{"label":"bad"}` без объяснений.
- Синтезатор: `gemini/gemini-4-argon`, до 32768 выходных токенов (включая thinking), таймаут 900 с.
- Routing: по готовому полю `topic`, один совет только для своей темы; в judge-запросе только `context` и `conversation`, gold не передаётся.
- Один бюджетный журнал на эксперимент и лимит $10; штатный scorer `src/evaluate.py`; `macro_topic_accuracy` как основная метрика.

## 2. Этапы pipeline

| | exp1 | exp3 |
|---|---|---|
| Разбор train | 150 запросов Flash, `analysis_prompt.md`, 3 параллельно, старт не чаще 1 / 4.1 с | запросов нет: таблица exp1 переиспользуется с проверкой хешей |
| Синтез | 1 запрос Argon | 2 запроса Argon: промпт со ссылками, затем обрезка ссылок |
| Инференс | 80 запросов Flash | 80 запросов Flash |
| Всего платных запросов | 231 | 82 |

## 3. Вход Argon

| | exp1 | exp3 |
|---|---|---|
| Исходный промпт | `baseline/prompt.md`, 128 слов, zero-shot | `seed_prompt.md`, 503 слова базы + 4 × 130–134 слова советов |
| Откуда исходный промпт | исходный baseline эксперимента | слияние синтезированных промптов exp1 и exp2 (зафиксировано в `manifest.seed_sources`) |
| Блок определений | нет | `definitions.md`, 14 кодов D1–D14, подаётся как часть базового промпта |
| Таблица кейсов | 150 строк: ID, тема, gold, baseline, флаг совпадения, комментарии А и Б | та же таблица |
| Размер входа | 39462 входных токена | 50065 входных токенов на два запроса |

Что именно вычищено из seed относительно промптов exp1 и exp2: служебные заголовки вида «Refines C1, C2 using D14», повторные перечисления кодов D в каждом пункте, самопротиворечивая оговорка exp1 про MXN («обычно принимается, хотя иногда отмечается при других ошибках») — сжата до допуска в C5, а примеры и границы удалены, потому что Argon строит их заново уже со ссылками. Из 15 определений exp2 удалён `D2 complete month`: он нигде не цитировался, его содержание вошло в `COMPLETE_MONTHS`; остальные 14 использовались и сохранены с непрерывной нумерацией.

## 4. Мета-промпт синтеза

| | exp1 (`synthesis_prompt.md`, 321 слово) | exp3 (`synthesis_prompt.md`, 918 слов + `strip_prompt.md`, 203 слова) |
|---|---|---|
| Рубрика качества | нет | таблица пяти критериев с колонками +1/0: ясные критерии, ясные приоритеты, ссылки на train-примеры, ясные границы, соответствие реализации |
| Требуемая структура | не задана, свободный текст | `TASK`, `CRITERIA` (нумерованные C1..Cn), `PRIORITY`, `BOUNDARIES` — в этом порядке, под заглавными заголовками |
| Приоритеты критериев | не требуются | обязателен порядок проверки, победитель при конфликте и метка по умолчанию |
| Границы разметки | не требуются | обязательна секция с условием, контрастными ссылками и требуемой меткой |
| Примеры из train | **запрещены**: «Do not embed training IDs, memorized amounts/dates, case-specific verdicts, few-shot examples» | **обязательны**: ≥1 ссылка у каждого критерия, ≥1 у каждого пункта совета, ≥2 контрастные у каждой границы |
| Формат ссылки | — | `[[ev: <8 символов ID> \| <good\|bad> \| <решающий фрагмент> \| <номер критерия>]]`, упоминать кейс можно только внутри спана |
| Работа с определениями | — | не переписывать, не пересказывать, не перенумеровывать; ссылаться на D1–D14; определение само по себе не нарушение |
| Документация решения | нет | поле `rubric_selfcheck`: по записи на строку рубрики, судье не отправляется |
| Лимит объёма | ≤300 слов базы, ≤180 на тему | ≤900 слов правил базы, ≤260 на тему, ссылки не считаются |
| Второй запрос | нет | вырезать только спаны: те же секции, номера, формулировки, коды D; правится лишь то, что ломает удаление (двойной пробел, висячая запятая, пустой пункт) |

## 7. Новые артефакты и проверки

Файлы, которых нет в exp1: `definitions.md`, `seed_prompt.md`, `linked_artifact.json`, `prompt_with_links.md`, `strip_input.json`, `strip_prompt.md`. Отсутствуют файлы exp1: `analysis_prompt.md`, `analysis_calls.jsonl`.

Новые поля `manifest.json` адаптации: `definitions_sha256`, `seed_prompt_sha256`, `seed_sources`, `strip_prompt_sha256`, `reused_analyses` (каталог, хеши таблицы и её манифеста, хеш промпта разбора, настройки разбора). Ушли: `analysis_prompt_sha256`, `concurrency`, `request_interval_seconds`.

Новые поля `summary.json` адаптации: `link_report`, `strip_report`, `rubric_selfcheck`, `linked_artifact_sha256`, `definitions_sha256`, `analysis_reused_from`, `analysis_new_api_calls`, `cost_usd_estimated_new`, `cost_note`.

Новые поля манифеста прогона: `linked_artifact_sha256`, `definitions_sha256`.

Проверки перед инференсом: exp1 сверяет статус адаптации, полноту, хеш артефакта, хеш скомпилированных промптов и их соответствие артефакту. exp3 добавляет хеш документированного артефакта и хеш блока определений — промпт судьи нельзя подменить, не сломав проверку.

Офлайн-проверки адаптации, которых в exp1 не было вовсе:

- `link_report`: число ссылок, различных кейсов, кейсов с ошибкой baseline, критерии без ссылки, битые спаны, несуществующие ID, ссылки с меткой, не совпавшей с экспертной.
- `strip_report`: остатки спанов и train-ID в промпте для инференса, сохранность секций и номеров критериев, список кодов D, дословные повторы строк определений, объём до и после и `similarity_to_mechanical_strip` — сходство ответа Argon с механическим удалением спанов.
- Жёсткая остановка: если в промпте для инференса остались спаны или train-ID, прогон падает с `strip_failure.json` и повторяется с `--restrip`.

## 8. Интерфейс и настройки

`train.py`: exp1 имеет `--limit` и `--analysis-only` (управление этапом разбора); exp3 вместо них `--analyses` (каталог готовой таблицы) и `--restrip` (переспросить обрезку, не переиспользуя сохранённый ответ). `.env`: exp3 не содержит `ANALYSIS_MODEL`, `ANALYSIS_MAX_OUTPUT_TOKENS`, `ANALYSIS_CONCURRENCY`, `ANALYSIS_REQUEST_INTERVAL` — этапа разбора нет. Тесты: `experiments/test_exp1.py` (5 проверок) против `experiments/test_exp3.py` (7 проверок: seed-бандл, вычищенные определения, валидация ссылок по таблице, отчёт об обрезке, вход второго запроса, загрузка артефакта, схемы).

Достигнутые цифры проверены штатным scorer'ом из CLI (`score-cli-check.json` в каталоге `runs/`). Два кейса на 80 — не статистически значимое преимущество; качество на private одним прогоном не установлено. In-sample прогон на train для exp3 не делался, у exp1 он есть (macro 0.963384).

## 11. Проверяемость объяснения

Главное содержательное отличие: у exp1 объяснение решения существует только как текст промпта, и связь правил с train-данными ничем не подтверждена. У exp3 каждое правило несёт ссылку на конкретные train-кейсы, а ссылки машинно проверены против таблицы: 135 ссылок, 106 различных кейсов из 150, 35 из них с ошибкой baseline, 0 критериев без ссылки, 0 выдуманных ID, 0 расхождений заявленной метки с экспертной. Промпт для инференса отличается от документированного ровно на эти ссылки: `similarity_to_mechanical_strip = 1.0` по базе и всем четырём темам.
