# Правила экспериментов

- Один эксперимент — одна подпапка с `README.md`: идея, отличие от baseline, точный запуск, результат и краткий вывод. Обязателен `infer.py`, который делает инференс и затем оценку официальным `src/evaluate.py`. `train.py` добавляется только при необходимости.
- Предмет эксперимента — промпт и способ его построения/применения. Инференс всегда обращается к выбранной LLM через LiteLLM и Pydantic-AI (`pydantic-ai-litellm`). В judge-инференсе для каждого диалога запрашивать structured output, валидируемый Pydantic: только `{"label":"good"}` или `{"label":"bad"}`. Для обучения разрешены отдельные структурированные схемы комментариев и артефактов, как А/Б и промпты в exp1. Не заменять вызов модели эвристикой и не присваивать метку при ошибке API/парсинга.
- Ключи и имя модели хранятся в `.env`; имя модели задаётся `MODEL`. Приоритет: окружение процесса → `.env` эксперимента → `.env` репозитория → `../.env`. Не печатать ключи, не сохранять их в результатах и не коммитить `.env`. В репозитории допустим только `.env.example` без секретов.
- Стараться тратить не больше **$10 на один эксперимент**, включая пробные запросы и повторы. До запросов оценить верхнюю стоимость, ограничить выходные токены и повторы, учитывать расход всех попыток в журнале эксперимента. При неизвестной цене остановиться. Превышение $10 требует явного разрешения пользователя.
- Убирать воду из промптов, ответов модели, документации и отчётов без потери смысла. Для baseline ответ модели содержит только метку; объяснения не запрашивать.
- Train можно использовать для адаптации, test labels — только для оценки после предсказания. Не передавать метки, переводы-дубликаты или результаты scorer в запрос judge. Zero-shot baseline не использует train для обучения или примеров в промпте; по запросу пользователя допустима отдельная оценка на train с удалением gold из входа. В таблицах явно указывать train/test. Сохранять выбранный язык входа.
- Оценивать весь диалог. Основная метрика — `macro_topic_accuracy` штатного scorer. Частичный прогон не выдавать за полный public score. Не переписывать scorer и исходные данные.
- Сохранять точный промпт, модель и доступное имя фактически ответившей модели, параметры, хеши входа/кода, версии зависимостей, предсказания, расход токенов/оценку USD и полный отчёт метрик. Алиас `latest` может измениться; не обещать полную детерминированность.
- Сохранять успешные ответы по мере выполнения, поддерживать продолжение без повторной оплаты готовых строк. При изменении входа, промпта, модели или параметров начинать новый запуск. Не перезаписывать чужие результаты.
- Проверять обвязку без платных API-вызовов; затем сделать один пробный реальный запрос и продолжить тот же запуск. Не запускать дополнительные платные сравнения без необходимости.
- После каждого полного эксперимента обновлять `RESULTS.md`: краткое описание, запрошенная/фактическая модель, все метрики штатного scorer, расход и ссылки на артефакты. Использовать `update_results.py`; baseline и baseline_gemma вызывают его автоматически. Частичные прогоны не включать в таблицу полных результатов.
